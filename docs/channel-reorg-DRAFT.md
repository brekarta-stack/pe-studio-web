## 새로 생긴 증거

`config/sns_lines.json`에 **실제로 운영 중인 SNS 라인이 4개뿐**임이 확인됐다:
`papercraft`(화·목) · `edu`(화) · `regen`(목) · `personal`=LinkedIn(월·수·금).
→ 원안의 "3사업 + 개인브랜드" 구조가 **실제 운영과 정확히 일치**한다. 재편 방향이 실측으로 뒷받침됨.

또 하나: SNS 발행 정책이 **"검토 후 수동 게시(자동 외부발행 없음)"** 로 명문화돼 있다.
→ 신 시스템도 이 정책을 유지한다(LinkedIn API 승인 전까지는 어차피 강제되기도 함).

## 실측이 바꾼 결론

원안은 "24채널 중 21개 전략부재"라는 자기점검 진단에 기반했다. 실제 설정 파일을 보니
**돈이 도는 라인은 4개(3사업 + 개인브랜드)뿐**이고, 그 4개는 요일·톤·타깃까지 이미 정의돼 있다.
즉 **재편의 실질은 "20개를 없애는 것"이 아니라 "이미 살아있는 4개만 신 시스템으로 옮기는 것"**이다.
나머지는 Slack 채널이라는 껍데기일 뿐 자동화가 붙어 있지 않다 → 이관 부담이 예상보다 훨씬 작다.

**따라서 게이트의 실제 질문은 3개로 줄어든다** (`domain-definition-DRAFT.md` 말미와 동일):
1. biz-b는 견적 사업인가 제안서 사업인가?
2. biz-b/biz-c 우선순위?
3. 분기 목표 숫자 (모르면 제안값으로 시작 후 실측 교정)
