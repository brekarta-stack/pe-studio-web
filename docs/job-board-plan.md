# 작업 공고 (선착순 배정) — 요구사항·설계

2026-11-13 운영자 요청. 들어온 문의를 운영자가 금액·마감일과 함께 공고로 올리면, 작업자가 포털에서
보고 **스스로 선착순으로 가져가는** 흐름. 기존 "제안 → 수락/거절"(1:1, `assignments.offer_status`)은
그대로 두고, 그 앞단에 공개 공고를 하나 더 얹는다. 가져가는 순간 기존 배정(`assignments`) 한 줄이
수락 완료 상태로 만들어지므로 작업 관리·정산·포털의 나머지는 손대지 않는다.

## 1. 확정된 결정 (2026-11-13 운영자 답변)

| 질문 | 결정 |
|---|---|
| 작업자에게 보이는 금액 | **견적가(고객 청구)와 작업비를 따로** 적는다. 작업자에게는 작업비만. 견적가·마진은 기존 규칙대로 비공개 |
| 네이버 메일 작업자 로그인 | **이메일 로그인 링크** 추가 (구글 로그인은 그대로 유지) |
| 캘린더 기록 | **구글 캘린더 API** 로 연결된 구글 계정(ask@papercraft.kr)의 기본 캘린더에 직접 등록 |
| 작업비 세금 | **부가세 방식** — 작업자가 세금계산서를 발행하고 작업비 + 부가세 10% 를 받는다. 가져간 배정은 `fee_tax_mode='vat'`. 입력·저장은 공급가, 화면·메일은 **부가세 포함가를 앞에** 보여 준다 |

## 2. 작업자 명단

| 작업자 | artists.id | 알림 메일 | 로그인 |
|---|---|---|---|
| 오세기 | artist-04 | ask@papercraft.kr | 관리자 계정이라 포털이 아니라 **관리자 화면에서** 가져간다 |
| 김철호 | artist-01 | finalpaper@naver.com | 포털 — 이메일 링크 |
| 박형미 | artist-03 | dinonabi@naver.com | 포털 — 이메일 링크 |

명단은 `src/lib/job-board-types.ts` 의 `WORKER_ROSTER`. 명단에 없는 작업자(문재호 등)도 승인된 포털 계정이
있으면 공고를 보고 가져갈 수 있고, 알림은 계정 이메일로 간다. 마이그레이션이 김철호·박형미 계정을
승인 상태로 넣는다(이미 그 아티스트에 계정이 있으면 건드리지 않는다).

## 3. 흐름

1. **문의 정리** — `/admin/jobs` 에 진행 중(활성 단계, Drop 제외) 문의가 한 줄씩 나온다. 고객 이름·연락처는
   운영자 화면에만 있다.
2. **공고 작성** — 줄마다 견적가(선택)·작업비(필수)·마감일(필수)·작업자 전달 메모를 적고 "공고 올리기".
   작업비와 마감일이 있어야만 올라간다. "작업자에게 메일로 알리기"(기본 켬)를 켜면 명단 전원에게 새 공고 메일.
3. **작업자 확인** — 포털 `/artist/jobs` 에 공고 중인 건만 보인다. 상세에는 작업비·마감일·전달 메모와
   의뢰 브리프(제품·수량·디자인·요청사항·첨부). **고객 이름·이메일·전화와 견적가는 조회 자체에서 뺀다.**
4. **가져가기** — 첫 번째로 누른 사람만 성공한다(`status='open'` 조건부 UPDATE 한 번). 늦게 누른 사람은
   "이미 다른 작업자가 가져갔습니다". 성공하면:
   - `assignments` 에 수락 완료(`offer_status=accepted`, `status=working`) 배정 생성 — 작업비·견적가·마감일·메모 복사
   - 공고는 `claimed` 가 되어 다른 작업자 목록·상세에서 사라진다(상세 URL 로 열어도 404)
   - 구글 캘린더에 마감일 종일 일정 등록. 실패해도 가져가기는 유지하고 사유를 공고에 남겨 관리자 화면에 표시
5. **마감 알림** — 가져간 시각 → 마감 시각(마감일 23:59 KST) 구간의 **50%·25%·10%** 가 남은 시점에 작업자에게 메일.
   - 여러 단계를 한꺼번에 지났으면(점검 공백) 가장 급한 단계 하나만 보내고 나머지는 보낸 것으로 친다
   - 배정이 완료·취소됐거나 마감이 지났으면 보내지 않는다
   - 보내기 전에 "이 단계 보냄"을 조건부로 먼저 찍어 두 점검이 겹쳐도 한 번만 나간다. 발송 실패면 되돌려 다음 점검이 재시도
6. **회수** — 관리자가 "배정 취소"하면 배정은 `cancelled`, 캘린더 일정 삭제, 공고는 다시 작성 상태(`draft`)로.
   "다시 공고"로 재오픈할 수 있다. 공고 중인 건은 "공고 내리기"로 내릴 수 있다.

## 4. 데이터 (마이그레이션 `20261113_job_board.sql`)

`job_postings` — 문의(quote) 하나에 공고 하나(`quote_id` UNIQUE, 재공고는 같은 줄을 고친다).

| 컬럼 | 뜻 |
|---|---|
| status | draft(작성·내림) · open(공고 중) · claimed(가져감) |
| client_amount | 견적가(고객 청구, 공급가액) — 작업자 비공개 |
| artist_fee / due_date / memo | 작업자에게 보이는 작업비(세전)·마감일·전달 메모 |
| opened_at / claimed_by / claimed_at / assignment_id | 공고·가져가기 기록 |
| calendar_event_id / calendar_error | 캘린더 등록 결과 |
| alert_50_at / alert_25_at / alert_10_at | 마감 알림 발송(또는 건너뜀) 시각 |

`artist_login_tokens` — 이메일 로그인 링크. 토큰 원문은 메일에만 있고 표에는 SHA-256 해시만. 15분 유효, 한 번 쓰면 소진.

RLS 켜고 정책 없음(서비스 롤 전용) — 기존 표와 같다.

## 5. 이메일 로그인 링크

- `/artist/login` 에 이메일 칸. 승인·매칭된 계정이면 15분짜리 링크를 보낸다. 계정 여부와 상관없이 같은 안내를 띄운다(가입 여부 노출 방지).
- 같은 이메일로 15분에 5번까지.
- 링크(`/artist/login/verify?token=…`)는 **버튼을 눌러야** 로그인된다 — 메일 보안 검사기가 링크를 미리 열어 토큰을 소진하는 일을 막는다.
- next-auth Credentials 공급자(`email-link`)가 토큰을 조건부 UPDATE 로 소진하고 이메일을 돌려주면, 그 뒤는 구글 로그인과 같은 `signIn`/`jwt` 판정을 탄다.

## 6. 캘린더

- 기존 구글 연결(견적서 화면 "구글 드라이브 연결")에 `calendar.events` 권한을 추가했다. **다시 연결해야 권한이 생긴다.**
- 일정은 연결된 계정의 기본 캘린더(`primary`)에 들어간다 → **ask@papercraft.kr 로 연결해야 한다.** 다른 계정이면 관리자 화면에 경고.
- `calendar.events` 는 구글 민감 권한이라 앱 검수 전에는 동의 화면에 "확인되지 않은 앱" 경고가 뜬다(고급 → 계속). 사용자 100명 이하라 동작에는 지장 없다.

## 7. 주기 점검

- `/api/cron/job-alerts` — `CRON_SECRET`(Vercel 크론) 또는 `OUTREACH_INTAKE_TOKEN`(맥 작업자) 인증.
- Vercel Hobby 는 크론이 하루 1회라 촘촘한 알림은 **맥 launchd 가 15분마다** 호출하고(`com.agent.job-alerts`), Vercel 크론(매일 09:00 KST)은 맥이 꺼졌을 때의 안전망.

## 8. 사람 손이 필요한 것

1. Supabase SQL Editor 에서 `supabase/migrations/20261113_job_board.sql` 실행
2. GCP 프로젝트 Agents-CES 에서 **Google Calendar API 사용 설정**
3. 배포 후 견적서 화면에서 구글을 **ask@papercraft.kr 로 다시 연결**(캘린더 권한 체크)

## 9. 하지 않은 것

- 작업자가 가져간 일을 스스로 반납하는 기능(관리자 회수만)
- 공고별 세금 처리 선택(기본은 부가세 방식, 다른 방식이 필요하면 가져간 뒤 작업 관리에서 바꾼다)
- 시트에서 미리 골라 둔 미제안(draft) 배정 정리 — 가져가기와 별개로 그대로 남는다
