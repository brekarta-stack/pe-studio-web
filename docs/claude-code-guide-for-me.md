# 내가 Claude Code를 잘 쓰기 위한 가이드 (2026-07-25, 인터뷰 기반)

> 사용자 답변: 막히는 것=① 세션 끊겨 맥락 날아감 ② 긴 명령 붙여넣기 실패 ③ 뭘 시킬 수 있는지 모름
> 맥락 전달=지금은 "그냥 바로 일을 시킨다" / 언어 기준 궁금 / 용도=인프라·개발·자동화·설계 전부.

## 0. 먼저 개념 정리 — 터미널 `claude` = Claude Code

같은 프로그램이고 **실행 위치만 다르다**.

| | 웹 창(claude.ai/code) | 터미널 `claude` |
|---|---|---|
| 파일 | 클라우드 복사본 | **내 기기의 진짜 파일** |
| 명령 | 샌드박스 | **내 기기에서 진짜 실행**(SSH·docker 다 됨) |
| 용도 | 설계·리서치·문서 | 실제 조작·구축 |

**세션 = 대화 하나.** 창을 닫으면 그 대화는 끝난다(`claude --resume`으로 되살리기는 가능).
기기 간 대화 공유는 안 된다 → 그래서 **맥락은 대화가 아니라 git 문서로 넘긴다**(이 프로젝트가 그렇게 해왔다).

## 1. [막힘 ①] 세션 끊겨 맥락 날아감 → **3줄 오프너**

새 세션마다 상황 설명 대신 이 3줄만 붙여넣으면 된다:

```
docs/HANDOFF.md와 deploy/STATE.md를 읽고 현재 상태를 파악해.
그다음 [하려는 일]을 진행해.
끝나면 STATE.md 갱신하고 커밋·푸시해.
```

- 이미 우리 레포엔 **HANDOFF(다음 할 일)** 와 **STATE(현재 상태 SSOT)** 가 있다. 이게 "저장된 맥락"이다.
- 세션 끝에 **"STATE.md 갱신하고 커밋·푸시"**를 시키는 습관이 다음 세션의 맥락을 만든다. (이게 핵심 루프)
- 긴 작업 중 세션이 끊겼으면: `claude --resume` 시도 → 안 되면 위 3줄로 새로 시작(문서가 있으니 손실 최소).

## 2. [막힘 ②] 긴 명령 붙여넣기 실패 → **붙여넣지 말고 시켜라**

지금까지 실패 원인: zsh의 `#` 주석·`!` 히스토리 확장·괄호 glob·SSH 중간 끊김.

**해결: 명령을 내가 붙여넣는 대신, Claude Code에게 "해줘"라고 말한다.**
- ❌ (옛 방식) 내가 스크립트를 복사 → 터미널에 붙여넣기 → 깨짐
- ✅ (새 방식) "NAS에 SSH해서 ~를 확인하고 고쳐줘" → **Claude Code가 직접 실행**

터미널 `claude`는 내 기기에서 도니까 SSH·docker·파일편집을 스스로 한다. 붙여넣기 왕복이 원래 필요 없다.
꼭 내가 실행해야 하면(GUI 등) **"스크립트 파일로 만들고 한 줄 실행 명령만 줘"**라고 요청 → 긴 원라이너 금지.

## 3. [막힘 ③] 뭘 시킬 수 있는지 모름 → **용도별 지시 예시**

내 4가지 용도별로, 이 정도까지 맡길 수 있다:

### 인프라 운영·수리
```
NAS 백본 상태를 점검하고(smoke-all.sh) 문제 있으면 고쳐줘.
미니(ssh agent@100.67.146.83)의 유령 알림을 원인 찾아서 꺼줘.
백업이 어제 성공했는지 확인하고 실패면 원인 분석해줘.
```
→ SSH·docker·cron·로그 분석까지 직접 한다.

### 프로덕트 개발(코딩)
```
~/repos/impact-ledger 를 읽고 구조를 요약해줘.
이 기능을 구현해줘: [설명]. 테스트도 같이 짜고 실행해서 통과 확인해줘.
```
→ **레포마다 `CLAUDE.md`를 두면** 세션이 그 프로젝트 맥락을 자동 장전한다(아래 §5).

### 자동화 만들기
```
n8n에 [이런] 워크플로를 만들어줘. LiteLLM 별칭은 write-ko-draft 쓰고,
승인 게이트는 Slack으로. 만들고 실행해서 E2E 통과 확인해줘.
```
→ 워크플로 JSON 작성·주입·실행까지 한다(우리 세션이 실제로 해온 방식).

### 설계·의사결정 상담
```
[상황]. 이 결정의 트레이드오프를 적대적으로 검토해줘.
근거 있으면 내 판단을 뒤집어도 좋아.
```
→ 이건 **웹 창이 더 적합**(리서치·병렬 검증 강함). 터미널은 실행이 강점.

### 어디에 뭘 시킬지 (기기 헷갈림 방지)
| 하려는 일 | 어디서 |
|---|---|
| 내 기기 조작(NAS·미니·파일) | **터미널 `claude`**(Studio) 또는 Orca |
| 설계·리서치·문서 | 웹 창(지금 이 대화) |
| 폰에서 지시 | Orca 앱 → Studio 세션 |

**프롬프트 확인법**: `seakimacultra@segiui-MacStudio` = Studio · `오세기@DXP4800PLUS-osk` = NAS · `PS C:\` = Windows.

## 4. 언어 — 한국어로 쓰세요 (기준)

- **지시는 한국어로 충분하다.** Claude는 한국어 지시를 정확히 이해하고, 영어로 바꿔 쓴다고 품질이 오르지 않는다.
  (영어가 유리한 건 "영어 문서를 다룰 때 그 용어를 그대로 쓰는 것" 정도.)
- **산출물 언어는 용도로 정한다** — 이 프로젝트에서 실제로 쓰는 기준:
  - **문서·주석·대화 = 한국어**(내가 읽을 것)
  - **커밋 메시지 = 영어**(git 관행, 도구 호환)
  - **코드 식별자 = 영어**(변수·함수명)
  - **대외 산출물(블로그·견적) = 한국어 + 프런티어 모델 고정**(로컬 모델 품질 미달 실측)
- 팁: 기술 용어는 영어 그대로 써도 된다("이 컨테이너 restart 정책 확인해줘") — 오히려 정확하다.

## 5. 레포 설정 — `CLAUDE.md`가 핵심 (한 번만 하면 계속 먹힘)

**레포 루트에 `CLAUDE.md`를 두면 그 폴더에서 연 세션이 자동으로 읽는다.** 매번 설명할 필요가 없어진다.

각 프로덕트 레포(impact-ledger 등)에 이런 걸 두면 좋다:
```markdown
# CLAUDE.md
## 이 프로젝트는
[한 줄 정체] · 고객: [누구] · 현재 단계: [idea/build/deliver]
## 기술 스택
[언어·프레임워크·DB]
## 실행·테스트
개발: `npm run dev` / 테스트: `npm test`
## 규칙
- 커밋 메시지는 영어, 문서·주석은 한국어
- [이 프로젝트만의 주의사항]
## 지금 하는 일
[현재 목표 1~2줄]
```

- 우리 시스템 레포엔 이미 `docs/CLAUDE.md`(설계 마스터)가 있다.
- **새 프로덕트를 Orca에 등록할 때 이 파일부터 만들어라** — 세션 품질이 확 오른다.

## 6. 알아두면 좋은 실전 습관 (이 프로젝트에서 검증된 것)

1. **세션 끝에 "STATE 갱신 + 커밋·푸시"** — 맥락 유실 방지의 유일한 확실한 방법.
2. **"~해줘" 대신 "확인하고 → 고치고 → 검증해줘"** — 검증까지 시켜야 "됐다고 했는데 안 된" 사고를 막는다.
   (실제로 "스키마 로드됨"이 거짓이었던 사고가 있었다.)
3. **위험한 건 물어보게 두기** — 삭제·재시작 같은 건 Claude가 확인을 구한다. 그 안전장치를 끄지 말 것.
4. **막히면 "왜 안 되는지 원인부터 찾아줘"** — 해결책을 바로 요구하기보다 진단을 시키면 정확해진다.
5. **긴 작업은 Studio에서** — 터미널을 닫아도 Orca/tmux면 계속 돈다(`docs/remote-dev-guide.md`).
